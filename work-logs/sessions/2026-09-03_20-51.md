**[21:10] 对抗性审查进展记录**

**工作内容：**
- 响应 Robert「做一遍全面的对抗性审查」指令，对 Scoped Literature Retriever 全链路执行对抗性压力分析，深挖 6 处攻击面与边缘漏洞并实施彻底加固：
  1. **跨论文 Segment ID 字典碰撞（Critical）**：发现 `corpus_build.py` 生成的段落默认 `content_id` 均为 `item-01`。原实现直接以 `segment_id` 作为 `build_collection` 键，后出现的论文段落会覆盖先出现论文，使集合大小折叠为 1 且导致全部论文与最后论文文本错误对比打分。修复：在 `load_eligible_candidates` 实施论文前缀全限定 `segment_id = f"{paper_id}:{content_id}"`。
  2. **语料重复 paper_id 与重复 content_id 拦截（High）**：加入 `seen_paper_ids` 与 `seen_content_ids` 判重集合，遇到重复记录立即 fail closed（`INVALID_CORPUS`）。
  3. **强制 Audit Release Gate，封堵零审计直接调用后门（High）**：`search()` 强制要求存在 `run_id` 与 `store`，若无 run 上下文直接调用 `search()` 立即 fail closed 抛出 `AUDIT_RELEASE_GATE_FAILED`，杜绝未留痕结果释放。
  4. **异构字典键防御（Medium）**：输入参数字典若含有非字符串键（如 `{1: "...", "query": "..."}`），`sorted(extra_keys)` 会在 Python 3 中抛出原生 `TypeError`；统一加固为 `sorted(str(k) for k in extra_keys)`，受控抛出 `INVALID_QUERY`。
  5. **全量输入异常留痕（Medium）**：Step 1 统一用外层 try-except 捕获所有参数错误（包括非 dict、未知参数、缺失 query），确保全量 `input_error` 均在私有证据链落盘 `audit.json` 并追加 `operation.failed` 事件。
  6. **零 Token 候选文献拦截（Medium）**：对齐原型 `schema.py`，标题或正文若无任何可检索 token（纯标点）立即 fail closed（`INVALID_CORPUS`）。
