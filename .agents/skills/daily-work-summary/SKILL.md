# 生成当日工作总结

当用户调用此 skill 时，读取当天所有的 session 记录文件，结合 git 信息，生成一份结构化的工作日报，并协助上传到 Notion。

## 步骤

### 1. 读取当日记录

**Session 记录文件：**
- 读取 `work-logs/sessions/` 目录下所有以今天日期（`YYYY-MM-DD`）开头的文件
- 如果没有找到任何文件，提示用户当天没有 session 记录，询问是否需要手动补充后再生成日报

**Git 记录：**
```bash
git log --oneline --since="today 00:00" --until="tomorrow 00:00" 2>/dev/null || echo "无 git 记录"
```

**交叉验证：**
检查 git log 中是否有 session 记录未覆盖的 commit。如有，在日报中补充说明这些未被记录的工作。

### 2. 生成日报

将所有 session 记录合并、去重、提炼，生成以下结构的日报。注意：日报是提炼，不是把 session 记录拼在一起。同一件事在多个 session 中出现时，合并为一条完整描述。

```markdown
# 工作日报 - YYYY-MM-DD

## 今日概要
（2-3 句话概括今天的核心进展和状态。这是管理者最先看的部分，要有信息量，不要写空话。）

## 完成的工作
（按主题分组，合并来自不同 session 的相关工作。）

- **主题 1**：具体描述
- **主题 2**：具体描述

## 实验结果
（如果今天有实验产出，用表格呈现关键结果。没有实验产出则省略此节。）

| 实验 | 关键指标 | 数值 | 对比 Baseline | 备注 |
|------|---------|------|-------------|------|

## 遇到的问题
（合并所有 session 中的问题，标注当前状态。如果某个问题在后续 session 中已解决，标注最终状态。）

- ✅ 已解决：问题描述 → 解决方案
- ❌ 未解决：问题描述（已尝试：...，卡在：...）
- 🆘 需要帮助：问题描述（影响范围和紧急程度）

## 今日决策记录
（如果今天做了重要的技术决策或方向选择，在此记录。省略琐碎决策，只记录会影响后续工作方向的选择。）

- **决策**：选择了什么
- **原因**：为什么这样选
- **替代方案**：还考虑了什么，为什么没选

## 失败的尝试
（今天尝试了但没有成功的方法，以及失败的可能原因。这部分信息对团队判断方向很有价值。没有则省略。）

## 明日计划
- （基于今天的进展和遗留问题，列出明天要做的事）

## ⚠️ 异常与风险
（如果有以下任何情况，在此高亮。没有则省略此节。）
（实验结果异常、进度严重落后、关键依赖不可用、连续多天同一问题未解决等）
```

### 3. 停滞检测

在生成日报时，自动检查以下信号并在"异常与风险"部分标注：

- 今天的 git commit 数量少于 3 条
- 有 session 记录但没有任何实验结果产出
- 存在标记为 🆘 的问题
- 同一个问题连续出现在多个 session 中仍未解决

### 4. 写入与确认

- 将日报写入 `work-logs/daily/YYYY-MM-DD.md`
- 将文件展示给用户确认，询问是否需要补充或修改

### 5. 协助上传到 Notion

日报确认后，询问用户是否需要上传到 Notion：

1. **首先检查当前环境中是否有可用的 Notion 相关 MCP 工具或 skill**（查找名称包含 "notion" 的工具）
2. **如果没有找到，直接询问用户**："你的环境中是否配置了 Notion 上传工具（如 Notion MCP server、CLI 工具等）？如果有，请告诉我如何使用；如果没有，你可以手动将日报内容复制到你的 Notion 页面。"
3. 如果用户提供了上传方式，按用户的指引协助完成上传
4. 如果用户表示没有上传工具，输出以下提示：

> 日报已生成：`work-logs/daily/YYYY-MM-DD.md`
> 请将内容手动复制到你的 Notion 页面。

不要自行猜测或尝试检测 Notion CLI 和 API 的可用性——直接问用户最可靠。

## 日报质量要求

- **合并而非堆砌**：把碎片化的 session 记录整合成连贯叙述，相关工作归到同一主题下
- **突出异常**：异常信号不能被淹没在正常内容中，确保管理者扫一眼就能看到
- **客观准确**：基于 session 记录和 git log 的客观事实生成，不添加、不美化、不隐瞒
- **决策可追溯**：重要决策要记录理由和备选方案，方便团队事后复盘
- **如实记录，不要粉饰**：管理者并不只根据最终产出的质量高低、任务进度是否理想来评价用户的工作，而更重视在完成任务的过程中体现出的人的能力——包括如何应对困难、如何做出判断、如何从失败中调整方向。所以，请不要粉饰用户遇到的困难和不顺，也不要淡化问题的严重性。真实的记录比好看的记录更有价值。
