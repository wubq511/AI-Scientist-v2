# 记录 Session 工作进展

此 skill 在每次 assistant 完成实质性回答后自动调用。为使其生效，请在项目的 CLAUDE.md（或对应 harness 的系统指令配置）中添加以下规则：

> 在每次完成实质性回答后，自动调用 record-session-progress skill 记录工作进展。

## 是否需要记录的判断

在自动调用时，先判断刚才的对话是否涉及以下任一情况。如果都不涉及，则跳过本次记录，不写入任何内容，也不输出任何提示：

- 代码被创建、修改或删除
- 实验被启动、完成或产出了结果
- 遇到了问题、报错或异常
- 做了技术选择或方向决策
- 完成了文献调研、数据处理等阶段性工作

以下情况不需要记录：简单的问答、闲聊、确认性回复、环境配置的常规步骤等。

## 步骤

### 1. 确定记录文件

- 文件目录：`work-logs/sessions/`，如果目录不存在则创建
- 文件命名：`YYYY-MM-DD_HH-MM.md`，使用当前日期和时间
- **关键**：检查本次 session 中你是否已经创建过记录文件（回顾对话历史）。如果是，继续追加到同一个文件，不要创建新文件。如果否，创建新文件。

### 2. 收集信息

从以下来源收集信息：

**对话上下文（主要来源）：**
- 用户在本次对话中做了什么具体工作
- 遇到了什么问题，如何处理的
- 做了哪些决策，为什么这样决策
- 实验运行情况及结果（如有）

**Git 记录（辅助来源）：**
运行以下命令获取近期 commit：
```bash
git log --oneline --since="6 hours ago" 2>/dev/null || echo "无 git 记录"
```

**实验指标（如有）：**
如果对话中运行了实验，提取关键指标（loss、accuracy、F1 等），记录具体数值。

### 3. 生成记录

如果是新建文件，先写入文件头：

```
# Session 记录 - YYYY-MM-DD HH:MM
```

然后追加以下格式的记录。如果是同一文件的后续追加，先写一行 `---` 作为分隔，再追加：

```
**[HH:MM] 进展记录**

**工作内容：**
- （具体描述做了什么。不要写"修改了代码"，要写"为了解决 X 问题，将 Y 模块的 Z 逻辑改为 W，因为..."）

**结果：**
- （实验数值、测试结果、或阶段性产出。没有则写"暂无产出"）

**问题与状态：**
- （遇到的问题及当前状态：✅ 已解决 / ❌ 未解决 / ⏳ 进行中 / 🆘 需要帮助）

**决策记录：**
- （如果做了选择——选了方法 A 而非 B、选了某个超参范围、决定放弃某条路线——记录选择和理由。没有重要决策则省略此块。）

**相关 Commit：**
- （commit hash + message，没有则写"无"）
```

### 4. 写入规则

- 如果本条记录和文件中上一条记录的内容有重叠，只记录新增的部分，不要重复
- 写入后简要告知用户记录已更新，一句话即可，不要复述完整内容
- 记录过程应尽量简洁高效，不要打断用户的工作节奏

## 记录质量要求

- **具体**：不要写"调整了超参数"，要写"将 learning rate 从 1e-3 降到 5e-4"
- **记录失败**：尝试了但没成功的方法必须记录，包括失败原因和已排除的方向
- **标记异常**：实验结果异常时（loss 不降反升、指标远低于 baseline、训练中断等）用 ⚠️ 标记，并简述异常表现
- **记录决策**：如果做了重要决策（选择了方法 A 而非方法 B、决定重新设计某个模块），记录决策及理由。这是管理者非常关心的信息
- **如实记录，不要粉饰**：管理者并不只根据最终产出的质量高低、任务进度是否理想来评价用户的工作，而更重视在完成任务的过程中体现出的人的能力——包括如何应对困难、如何做出判断、如何从失败中调整方向。所以，请不要粉饰用户遇到的困难和不顺，也不要淡化问题的严重性。真实的记录比好看的记录更有价值。
